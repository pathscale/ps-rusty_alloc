# Benchmarks

## Method

- Machine: Apple M4 Max, 16 cores, 64 GB, macOS 26.5, rustc 1.98.1. Shared
  workstation with load average around 10 during runs, so every number is the
  minimum over rounds, not a mean.
- One release binary per allocator (`lto = "fat"`, `codegen-units = 1`,
  `panic = "abort"`), built by `bench/build.ts`. `rusty_alloc` goes through a
  `GlobalAlloc` shim (`bench/src/ra_shim.rs`) with the same logic as the
  published `rusty_alloc-api` 2.2.6, pointed at this fork.
- `bench/run.ts` interleaves A/B: each round rotates the allocator order and
  reverses it on odd rounds, so drift in machine load hits every allocator
  alike. 5 rounds (7 for the RSS fix runs), min per metric.
- Each process runs under `/usr/bin/time -l`: wall ms (printed by the binary),
  instructions retired, cycles elapsed, maximum resident set size, peak memory
  footprint.
- Ratios are against mimalloc 0.1.52 (C); lower is better.
- Raw JSONL and summaries for every run are in `bench/results/`.

Workloads (`bench/src/main.rs`, `name:threads`):

| name | shape |
|---|---|
| small | ring of 1024 live blocks, 16-255 B, random free and refill, 20M ops per thread |
| xthread | producer/consumer pairs, 16-255 B in batches of 256, every free cross-thread |
| realistic | build and drop String/Vec/HashMap structures with reallocs |
| tasks | async-runtime shape on one thread: boxed futures 32-512 B in a 4096-slot ring, polled and dropped out of order, Arc<[u8]> clone churn, iterator collects |
| tasksbig | tasks with 256K live tasks (about 100 MB working set) |
| phases | 8 phases of 64 MB of one size class, 90% freed at random, 10% survive |
| workers | 8 waves of t threads, each builds about 24 MB of maps and strings, drops, exits |
| large | 4 KB-1 MB, 32 live per thread, every page touched |

## Verdict

rusty_alloc 2.2.6 is the only pure-Rust allocator here that keeps pace with
mimalloc. On `tasks:1` it runs 0.94x wall and 0.91x instructions, `small:1`
0.90x / 0.64x, `large:1` 0.72x / 0.38x. The one loss is `xthread:1` at 1.31x wall.

Other pure-Rust allocators:

- smalloc (`smmalloc` 7.6.13): fast, but 6-10x mimalloc RSS on `workers`.
- baby-mimalloc 0.2.1, rlsf 0.2.3, dlmalloc 0.2.14: one global lock or a
  single-arena design; 1.3x to about 150x slower depending on workload (under 4 threads, single-round early run: baby-mimalloc `small:4` 18.8 s vs 127 ms, rlsf and dlmalloc 76-89x; single thread: baby-mimalloc
  `large:1` 27x, rlsf and dlmalloc `small:1` 5x, `phases:1` 2.7x).
- ferroc: does not build.

churning large allocations that is a trap; the resident budget gets the RSS
without it.
